# 지능형 기동지원 군사상황 정보판단 프로그램

> 이어서 작업하는 경우 먼저 [HANDOVER.md](HANDOVER.md)(인수인계 정리)를 읽으세요.

출발점과 도착점을 정하면 기동로(이동 경로)를 찾습니다. 그 경로 위에 있는 공개 도로 CCTV를 실시간으로 AI 분석해서 구간별 통행 상황, 종합 판단, 조치 건의가 담긴 상황 보고를 만듭니다.

새 장비 없이 이미 깔려 있는 민간 공공 인프라(국가교통정보센터 CCTV)를 활용하는 저비용 기동 상황인식 도구입니다.

## ISR·UAV 위협 분석 (2026-11-09 추가)

공개 도로 CCTV(교통)에 더해, ISR·UAV 사진·영상에서 기동로 위의 위협 후보를 찾아 구간별 **기동 가능성**을 판단합니다.

| 구분 | 내용 |
|---|---|
| 입력 | 🛰️ ISR·UAV 영상 패널에서 사진·영상을 올리고 기동로 위 위치(km)를 지정. 시연 모드는 공개 훈련·호송 사진 2장이 미리 배치됨 |
| 탐지 | YOLOE-26s에 글로 대상 지정 (학습 없음): 기갑·화력 차량, 군용 차량, 병력, 도로 장애물·파손, 연기·화재. 민간 차량·사람 문구도 넣어 오인을 줄임 |
| 위협 수준 | 위험 / 경계 / 주의 / 없음. 세부 종류(전차·장갑차 등)는 자주 헷갈려서 묶음으로 판단하고 종류는 '추정'으로만 표시. 신뢰도 0.40 미만이면 '경계(확인 필요)'로 낮춤 |
| 기동 가능성 | 교통과 위협 중 나쁜 쪽: 기동 불가(No-Go) = 돌발상황 또는 위협 '위험' / 제한적 기동(Slow-Go) = 서행·정체 또는 위협 주의·경계 / 기동 가능(Go) |
| 우회로 | 기동 불가 지점이 있으면 OSRM 대체 경로를 찾고, 없으면 위협 지점 옆(좌우 10~20km)을 거치는 경로를 만들어 2km 이상 회피하는 가장 빠른 길을 건의 (지도에 보라색 점선) |
| 보고서 | 위협 정보, 구간별 기동 가능성, 우회로·추가 정찰 건의 포함 |

- **분할 탐지:** 가로·세로 1000px 이상인 영상은 전체 화면과 2×2 겹침 조각을 함께 탐지해 작은 차량을 덜 놓칩니다. 겹친 상자는 하나로 합칩니다.
- **동영상 확인 규칙:** 같은 위협이 2장면 이상, 분석 장면의 25% 이상에서 보여야 인정합니다. 아니면 '일시 탐지'로 보고 주의 수준으로 낮춥니다. 민간 고속도로 영상 2개로 시험했을 때 거짓 위협은 0건이었습니다.
- **결과 이미지:** 상자에 한글 이름표(위협 수준 · 종류 · 신뢰도)를 붙이고, 사람은 모자이크 처리합니다.
- **문구 실험 (2026-11-09):** 문구 세트 4가지와 시각 예시(전차 사진 1장)를 시험했습니다.
  - 시각 예시는 M551 전차를 맞혔지만, 보급 트럭을 전차로 오인했습니다.
  - 그래서 현재 문구 세트와 묶음 판단을 유지했습니다. 세부 종류 구분은 군 데이터로 추가 학습해야 개선됩니다.
- 위협 대상 문구를 바꾸려면 `src/threat_classes.py`를 고친 뒤 `.venv\Scripts\python.exe build_threat_model.py`를 실행합니다. 이때만 `models/mobileclip2_b.ts`(242MB)가 쓰입니다.
- 판단 보조용입니다. 사격·타격 지정 기능은 없고, 사람은 수만 세며 모자이크 처리합니다.
- 시연용 ISR 사진 출처: `data/isr/SOURCES.md`

## 지점 주변 융합 분석 (📍 탭)

기준 지점 반경 안의 공개 도로 CCTV(교통)와 ISR·UAV 영상(위협)을 함께 분석해 지역의 기동 가능성을 판단합니다.

- **기준 지점:** 도시 목록, 좌표 입력, 지도 클릭 중 하나로 정합니다. 분석 반경은 0.5~5km입니다.
- **ISR 위치:** 기준 지점에서의 **방위(북=0°)와 거리(km)**로 지정합니다.
  - 업로드하거나 시연용 사진을 고를 수 있어요.
  - 시연 모드에는 060° 1.8km(기갑 차량), 250° 2.6km(호송 행렬) 두 건이 미리 들어 있습니다.
- **종합 판단:** 교통 최악 단계와 위협 최고 수준을 합쳐 Go / Slow-Go / No-Go로 판단하고, 가장 가까운 위협의 방위와 거리를 함께 보여줍니다.
- **지도:** 분석 반경 원을 종합 판단 색으로 칠하고, 기준 지점에서 위협 지점까지 점선을 그립니다. 위험 지점에는 반경 500m 원을 표시해요.
- **보고서:** "지점 주변 군사상황 정보판단 보고" 형식으로 위협(방위·거리), 교통, 조치 건의를 담습니다.
- **시연 모드:** 실제 CCTV(서초·양재·원지동) 중 반경 안의 것과, 기준 지점 주변에 가상 배치한 샘플 영상 1개를 씁니다.

## 주요 기능

| 기능 | 내용 |
|---|---|
| 기동로 탐색 | 출발점·도착점 → OSRM(OpenStreetMap 도로망)으로 경로, 거리, 평시 예상 시간 |
| 경로 위 CCTV 선택 | 경로에서 0.3km 안의 고속도로·국도 CCTV를 찾고, 경로 전체에 고르게 N개 선택 |
| 구간별 상황 판단 | CCTV마다 원활·서행·정체·돌발 의심 판단 → 지도에 경로를 색으로 표시 |
| 상황 보고 자동 생성 | 일시, 기동로, 종합 판단, 구간별 상황, 조치 건의를 보고 형식으로 정리하고 .txt로 내려받기 |
| 지점 주변 분석 | 한 지점 반경 안의 CCTV 분석 (보조 기능) |

### 영상분석 방법

| 항목 | 방법 |
|---|---|
| 교통 (원활·서행·정체) | YOLO11n 차량 탐지 + ByteTrack 추적 → 멈춘 차량 비율 (20% 넘으면 서행, 50% 넘으면 정체) |
| 돌발상황 의심 | 대부분 움직이는데 1~2대만 8초 이상 안정적으로 멈춰 있을 때 |
| 기상·시야 | 밝기·대비·선명도 규칙 (참고용 추정) |
| 개인정보 보호 | 얼굴·번호판 인식 없음, 사람 영역 모자이크, 특정 인물·차량 추적 없음 |

## 실행

```
cd cctv_demo
.venv\Scripts\streamlit.exe run app.py
```

1. 브라우저에서 http://localhost:8501 이 열립니다.
2. **🛣️ 기동로 분석** 탭에서 출발점과 도착점을 고릅니다. 목록에 없으면 "직접 입력"을 고르세요.
3. **기동로 CCTV N개 분석 시작**을 누릅니다.
4. CCTV 6개 기준 약 1.5분 뒤 종합 판단, 구간별 지도, 상황 보고가 나옵니다.

왼쪽 사이드바에서 분석할 CCTV 수, CCTV당 분석 시간, 검색 폭을 바꿀 수 있습니다.

ITS API 한도가 초과됐거나 인터넷이 불안할 때 사이드바의 **시연 모드**를 켜세요.

- 나머지 구간은 공개 샘플 영상을 기동로 위에 가상으로 배치해 끝까지 시연합니다.
- 저장한 영상 주소는 만료될 수 있습니다. 만료되면 그 구간은 "영상 수신 실패"로 표시됩니다.

### 화면 구성

| 영역 | 내용 |
|---|---|
| 상단 | 모드 표시 띠, 단계 표시(① 기동로 설정 → ② CCTV 영상 분석 → ③ 상황 판단·보고), 요약 카드 |
| 종합 판단 | 색 띠로 표시 (초록 양호 / 노랑 서행 / 주황 정체 / 빨강 돌발) |
| 기동로 구간 띠 | 출발~도착을 한 줄 막대로 그리고 구간별 색과 CCTV 위치 표시 |
| 지도 | 구간별 색 경로와 CCTV 마커. 바탕 지도는 🗺️ 일반(OpenStreetMap) / 🛰️ 위성(Esri World Imagery) / 🌙 상황판(어둡게) 중 선택 |
| 결과 탭 | 📷 CCTV 화면 모아보기 / 📋 구간별 상황 / 📝 상황 보고(.txt 내려받기) / 🔍 상세 분석 |
돌발상황을 판단하려면 분석 시간이 10초 이상이어야 합니다.

## 데이터 출처

- **CCTV 영상:** 국가교통정보센터(its.go.kr) CCTV 화상자료 Open API. `.env`의 `ITS_API_KEY`가 필요합니다.
  - `.env`가 없으면 공개 샘플 영상 데모로 동작하지만, 기동로 분석에는 실제 키가 필요합니다.
- **경로:** OSRM 공개 서버(router.project-osrm.org). 연결이 안 되면 직선 경로로 대신합니다.
  - 공개 서버는 시연용이라, 실제 운용 시에는 자체 경로 서버가 필요합니다.
- **출발·도착 목록:** 공개된 도시 중심 좌표만 들어 있고, 부대 위치는 넣지 않았습니다.

## 실제 CCTV에서 확인한 오탐과 대응 (2026-11-09)

- **화면 글자를 차량으로 인식:** CCTV 화면에 찍힌 지점명·숫자("양재", "415")가 차량으로 탐지됐습니다.
  - 측정해 보니 박스 흔들림이 0.03 미만으로, 실제 차량보다 훨씬 고정돼 있었습니다.
  - 그래서 흔들림이 0.03 미만이고 신뢰도가 0.75 미만인 탐지는 "고정 물체"로 빼고 판단합니다.
- **원근:** 멀리 있는 차는 화면에서 조금만 움직입니다. 그래서 이동량을 픽셀이 아니라 차량 길이 단위로 잽니다.
- **추적 ID 뒤바뀜:** 차가 빽빽하면 이웃 차량끼리 추적 ID가 바뀌어 가짜 정차가 생깁니다(흔들림 0.17~0.21). 돌발 판단에서는 흔들림 0.12 이상인 후보를 뺍니다.
- **정체 줄:** 잠깐 섰다 가는 차는 돌발이 아니라 정체로 봅니다.
- **검증 사례:** 기흥휴게소 CCTV 화면에 표시된 "[정체] 교통량 증가"와 프로그램의 "정체" 판단이 일치했습니다.

## 한계 (발표 시 밝힐 점)

- **상·하행 구분 없음:** 한쪽 방향만 막혀도 전체로 섞여 판단됩니다. 기동로 판단에는 방향이 중요하므로 다음 보완 1순위입니다.
- **CCTV 사이 구간:** 분석한 CCTV 사이 구간은 가까운 CCTV 결과로 추정합니다.
- **판단 기준값:** 서울~천안 구간 CCTV 일부로만 맞춘 값입니다.
- **기상 판단:** 규칙 기반이라 정확도가 낮습니다.
- **사람 탐지 정확도:** 위에서 똑바로 내려다본 영상에서는 사전학습 모델이 잘 틀립니다.
- **처리 속도:** 노트북 CPU 기준으로 CCTV 1개에 약 15초 걸립니다. GPU가 있으면 훨씬 빨라집니다.
